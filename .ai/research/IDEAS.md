# Research: ideas for a phone-in-pocket Cardputer

Overnight research (2026-11-13) on features and projects for Tasca. Constraint: BLE only to a bonded iPhone (ANCS, AMS, HID), earphones on the iPhone. Goal: take the iPhone out as little as possible. Notes only: nothing here is approved; an idea becomes work through `/sdd:po`.

Legend: **Feasibility** high / medium / low on iOS with BLE only. **Effort** S (days) / M (a week) / L (more).

Ranked by value for "phone in pocket" against effort and certainty. Each line points to its round below. Nothing here is a spec yet.

## Findings

### Music: Apple Media Service (AMS) — Spotify, Apple Music, podcasts

- **What**: a "Now playing" screen: title, artist, app name, play state, volume; keys for play/pause, next, previous, volume, shuffle/repeat. Works with any app that publishes to iOS Now Playing, Spotify included.
- **How**: AMS is a GATT service on the iPhone, like ANCS (service `89D3502B-0F36-433A-8EF4-C502AD55F8DC`). Three characteristics: Remote Command (write a command ID; notifies which commands are available now), Entity Update (subscribe to Player / Queue / Track attributes, then receive changes), Entity Attribute (read the full value of a truncated one). Needs the same encrypted, bonded link Tasca already has.
- **Caveats**: a successful command only means iOS forwarded it to the player. Subscribe to Entity Update before any write. AMS may be published or unpublished at runtime: watch Service Changed. Adafruit notes Spotify may put artist and album into the title field when playing on a remote device. The spec's attribute list has no elapsed time as its own attribute; it comes inside Player PlaybackInfo (state, rate, elapsed) — to be confirmed against the spec appendix when written.
- **Alternative without AMS**: HID consumer usages (Play/Pause 0xCD, Scan Next 0xB5, Scan Previous 0xB6, Volume Up/Down 0xE9/0xEA, Mute 0xE2) through the existing consumer report: control without any metadata. Reported working on iOS by Nordic forum users. Tasca already sends consumer usages (Eject, Voice Command), so this is the cheapest step.
- **Feasibility**: high. **Effort**: HID keys S; AMS screen M. No GATT change on the Cardputer's side (AMS is a client role, like ANCS), so no re-pairing.
- **Fit**: very good — skip a song, change volume, see what plays, phone in pocket.
- **Sources**: [Apple AMS spec](https://developer.apple.com/library/ios/documentation/CoreBluetooth/Reference/AppleMediaService_Reference/Specification/Specification.html), [Adafruit Now Playing AMS display](https://learn.adafruit.com/now-playing-bluetooth-apple-media-service-display?view=all), [Moddable AMS client on ESP32](https://moddable.com/blog/ams-client/), [CircuitPython AMS API](https://docs.circuitpython.org/projects/ble_apple_media/en/latest/api.html), [Nordic: HID audio control with iOS](https://devzone.nordicsemi.com/f/nordic-q-a/45436/hid-audio-control-with-ios), [Bumble AMS profile](https://sources.debian.org/src/python-bumble/0.0.225-1/bumble/profiles/ams.py).

### Instagram, Telegram and other chat apps

- **What**: read DMs from Instagram, Telegram, Signal, Messenger like WhatsApp today.
- **How**: they all reach ANCS as notifications (Social category), with the app identifier telling them apart. Tasca already receives them and skips everything not WhatsApp. Showing them is a filter change plus an app label on the Chat.
- **Replies**: no wearable can reply to iPhone notifications directly: Apple gives ANCS no "reply with text" action (Fitbit, Huawei, Garmin all document iOS as read-only; Amazfit replies only through a Beeper cloud bridge). Tasca's way stays the same: open the chat on the iPhone (or Siri: "reply on Telegram") and type in Keyboard mode.
- **Feasibility**: high for reading; replies only through Keyboard mode or Siri. **Effort**: S–M (per-app label, the 56 KB store shared among more apps).
- **Fit**: good for reading. Instagram DM previews depend on Instagram's own notification settings.
- **Sources**: [Amazfit: replying on iOS](https://us.amazfit.com/pages/how-to-reply-to-ios-message-notifications-on-amazfit-devices), [Fitbit: iOS quick replies](https://community.fitbit.com/t5/Other-Versa-Smartwatches/iOS-social-media-apps-quick-reply/td-p/3285205), [Huawei: no replies with iPhone](https://consumer.huawei.com/ph/support/content/en-us15862330).

- [NXP ANCS/AMS client example](https://docs.mcuxpresso.nxp.com/mcuxsdk/24.12.00/html/examples/wireless_examples/bluetooth/ancs_c/readme.html): one client for both services, a good structural reference.

- Nordic forum: answering calls through HID consumer usages did not work on iOS — confirms the ANCS action route chosen for incoming calls.

### Shortcuts on a key: Full Keyboard Access commands (round 2)

- **What**: a Cardputer key combination runs any iOS Shortcut: start a Spotify playlist, set a timer, send "running late" with location, toggle Focus, read the next event, call someone, start a voice memo. Shortcuts runs on the iPhone, phone in pocket.
- **How**: on the iPhone, Settings > Accessibility > Keyboards > Full Keyboard Access on, then Commands > (bottom) Shortcuts section: pick a shortcut and press a key combination on the keyboard. Tasca only has to send that combination as a normal HID report (e.g. Ctrl+Opt+Cmd+1..9 from a Tasca key such as Opt+digit). No firmware change beyond a key map; the binding lives on the iPhone.
- **Two-way trick**: a Shortcut can end with "Show Notification"; the notification reaches the Cardputer over ANCS like any other. So a Shortcut can answer back on the Cardputer screen: weather, next calendar event, iPhone battery, the clipboard, a reply from ChatGPT/Siri. Tasca would show the Shortcuts app's notifications (today filtered out) — e.g. as a small "Result" Banner.
- **Caveats**: Full Keyboard Access also shows a focus border and turns other keys into commands; the Clicks guide suggests Auto-Hide 1–2 s and clearing unused commands. Whether bindings fire while the iPhone is locked is not documented: to be tested (Siri via Fn+Enter works locked). Many Shortcut actions need the iPhone unlocked (personal data).
- **Feasibility**: high (keys) — medium for "locked" use, to be tested. **Effort**: S for the key map; S–M for showing Shortcuts results.
- **Fit**: excellent: turns the Cardputer into a programmable remote with feedback, with no app on the iPhone.
- **Sources**: [Clicks: custom shortcuts via Full Keyboard Access](https://discover.clicks.tech/under-radar-unlock-clicks-power-keyboard-custom-shortcuts), [Clicks: keyboard as remote control](https://discover.clicks.tech/how-turn-clicks-keyboard-iphone-remote-control-your-life), [Apple: control iPhone with an external keyboard](https://support.apple.com/en-bn/guide/iphone/ipha4375873f/ios), [AbilityNet: external keyboard in iOS 26](https://mcmw.abilitynet.org.uk/how-to-control-your-device-using-an-external-keyboard-in-ios-26-on-your-iphone-or-ipad).

### Calendar, Mail, Maps (round 2)

- **Calendar and Mail**: their notifications arrive over ANCS in their own categories (Schedule, Email) and are skipped today. Showing event reminders ("Meeting in 10 min, Room 3") and mail sender + subject is a filter and label change, like other chat apps. Mail previews depend on Mail's notification settings. **Feasibility** high, **Effort** S–M.
- **Upcoming events on demand**: no BLE service exposes the calendar. Route: a Shortcut ("Find calendar events today" + "Show Notification") bound to a key, see above.
- **Maps navigation**: Garmin users report Apple Maps turn-by-turn alerts do not reach third-party watches: the next turn is a Live Activity, not a notification. No BLE-only route found. Google Maps pushes directions only to its own watch apps. **Feasibility** low; skip.
- **Sources**: [Garmin forum: iPhone Maps turn-by-turn](https://forums.garmin.com/sports-fitness/healthandwellness/f/venu-2/279208/feature-request---iphone-maps-turn-by-turn-notifications), [TechRadar: Google Maps on Garmin](https://www.techradar.com/health-fitness/smartwatches/garmin-just-gave-some-of-its-smartwatches-a-big-google-maps-upgrade-heres-which-models-are-getting-it), [Apple: directions on Apple Watch](https://support.apple.com/guide/watch/apdea7480950).

### Open-source watches and Cardputer firmwares (round 3)

- **Bangle.js iOS integration** (Espruino): the closest project to Tasca. ANCS for every app's notifications, optional time sync with the iPhone, and — the key point — **weather, calendar and location pushed by iOS Shortcuts as notifications that the watch parses**, then deletes on receipt (ANCS negative action = clear). Shortcut names must stay fixed so the watch recognises them; a Focus automation can hide them on the iPhone. This validates the "two-way Shortcuts" idea of round 2 and gives a ready protocol to copy (structured text in a notification of a known Shortcut). Sources: [BangleApps ios README](https://github.com/espruino/BangleApps/tree/master/apps/ios), [Bangle.js app loader](https://banglejs.com/apps/?id=ios).
- **InfiniTime / InfiniLink** (PineTime): iOS support needs a companion app; ANCS and AMS were delayed, and iOS bonding clashed with their secure bonding. Lesson: Tasca's "no app on the iPhone" path (ANCS + HID) is the robust one. Sources: [InfiniLink](https://github.com/InfiniTimeOrg/InfiniLink/releases), [InfiniTime issue 920](https://github.com/InfiniTimeOrg/InfiniTime/issues/920), [Apple forum: ANCS and Service Changed](https://developer.apple.com/forums/thread/771475).
- **Time sync idea**: Bangle.js syncs the clock from iOS. iPhones are commonly reported to expose the Bluetooth Current Time Service (CTS, 0x1805) to bonded accessories — to verify on the user's iPhone. Use: a clock in the status bar and correct "today" times without Wi-Fi. **Feasibility** medium (verify CTS), **Effort** S. Fallback: the ANCS notification date already carries local time.
- **Cardputer firmwares**: [Cardputer firmware list](https://github.com/ru84r8/Cardputer-firmware-list), [awesome-m5stack-cardputer](https://awesome.ecosyste.ms/projects/github.com%2Fterremoth%2Fawesome-m5stack-cardputer), [M5Launcher](https://github.com/bmorcelli/Launcher) (boot several firmwares from SD, OTA), [Bruce](https://github.com/pr3y/Bruce) (has a BLE keyboard mode), [M5Cardputer-BLE-HID-Keyboard](https://github.com/Gitshaoxiang/M5Cardputer-BLE-HID-Keyboard). None found doing ANCS/AMS for iPhone: Tasca seems unique on the Cardputer. Idea: make Tasca installable from M5Launcher (publish a `.bin` release) once the repo is public. **Effort** S.

### ANCS actions on ordinary notifications; Current Time Service (round 4)

- **Clear a notification on the iPhone from the Cardputer**: ANCS gives each notification a positive and/or a negative action, flagged in EventFlags and labelled by the PositiveActionLabel / NegativeActionLabel attributes. On ordinary notifications the negative action is usually "Clear" (Bangle.js uses it to delete Shortcuts notifications on receipt); the positive one is app-defined. Idea: a key on the Chat screen (or "Clear all" in the Inbox) clears the Chat's WhatsApp notifications on the iPhone too — lock screen tidy without taking it out. Fits the existing mirror rule (a notification removed on the iPhone is deleted on the Cardputer): the removed event closes the loop. Same Control Point command as the incoming-calls feature, so it is nearly free once that exists. **Feasibility** high (labels to read on the user's iPhone first, they may be absent for WhatsApp). **Effort** S after incoming-calls. Sources: [Nordic ANCS client sample](https://nrfconnectdocs.nordicsemi.com/ncs/latest/nrf/samples/bluetooth/peripheral_ancs_client/README.html), [nRF5 ANCS client app](https://docs.nordicsemi.com/r/bundle/nrf5_sdk_v17.1.1/page/ble_sdk_app_ancs.html).
- **Current Time Service (CTS 0x1805)**: iOS implements CTS internally; reports agree it is readable only by a bonded accessory (Nordic CTS client sample read the time from an iPhone 7, and stopped when pairing was disabled). Tasca is bonded, so a GATT client read (as for ANCS) should work. Use: clock in the status bar, "today/yesterday" labels, time even before any notification arrives. Also notifies on time-zone or DST change. **Feasibility** medium-high (test on the user's iPhone). **Effort** S. Sources: [Nordic: CTS on iPhone](https://devzone.nordicsemi.com/f/nordic-q-a/36526/current-time-service-on-nrf-connect-iphone-app), [Apple forum: iOS CTS](https://developer.apple.com/forums/thread/94248), [card10: read date/time from iOS](https://git.card10.badge.events.ccc.de/card10/firmware/-/merge_requests/406).

### iPhone battery; Type to Siri revisited (round 5)

- **iPhone battery on the Cardputer**: no source shows an iPhone exposing its own Battery Service (0x180F) to an accessory; iOS reads accessories' batteries, not the other way. BLE-only routes: (a) a personal Shortcuts automation "When battery level falls below 20 %" ending in "Show Notification" — arrives over ANCS like any notification; (b) a Shortcut bound to a key (round 2) that reports the level on demand. **Feasibility** medium (relies on the Shortcuts route). **Effort** S once Shortcuts notifications are shown. Sources: [Apple forum: BLE battery service](https://developer.apple.com/forums/thread/77866), [esp32.com: battery level iOS](https://esp32.com/viewtopic.php?p=90863).
- **Type to Siri, revisited**: the old Accessibility "Type to Siri" switch replaced voice Siri (the reason the user rejected it in siri-reply). With Apple Intelligence (iOS 18.1+), Type to Siri is a separate gesture (double-tap the bottom edge) that coexists with voice Siri, works from the Lock Screen, and accepts a Bluetooth keyboard; iOS 18.2 adds a Control Center / Lock Screen control for it. No documented hardware-key trigger on iPhone (on Mac: Command twice). Idea to test: whether Full Keyboard Access can bind "Type to Siri" or a Shortcut that opens it — then Fn+Enter = voice, another key = typed Siri, both native. Depends on the user's iPhone supporting Apple Intelligence. **Feasibility** to test. **Effort** S. Sources: [iMore: Type to Siri on iOS 18](https://www.imore.com/ios/how-to-type-to-siri-on-ios-18-and-why-its-made-me-use-it-more), [iDownloadBlog: type to Siri](https://www.idownloadblog.com/?p=886938), [Tom's Guide](https://tomsguide.com/ai/apple-intelligence/how-to-use-apple-intelligences-type-to-siri-feature-on-your-iphone), [PopSci](https://www.popsci.com/diy/how-to-use-type-to-siri/).

### Finding the iPhone; camera shutter (round 6)

- **Ring the iPhone**: no standard way. Immediate Alert Service runs the other way (the phone alerts an accessory); ringing the phone needs an app. BLE-only route: a Shortcut bound to a key (round 2) that sets the volume to 100 % and plays a sound — works while the link is up, i.e. the phone is within ~10 m. **Feasibility** medium (test with the iPhone locked). **Effort** S (iPhone-side Shortcut + a key). Sources: [Apple bluetooth-dev list: IAS direction](https://lists.apple.com/archives/bluetooth-dev/2014/Feb/msg00016.html), [Nordic: IAS client on iOS](https://devzone.nordicsemi.com/f/nordic-q-a/21684/how-to-setup-immediate-service-alert-client-ios), [Espressif IAS](https://docs.espressif.com/projects/esp-iot-solution/en/latest/bluetooth/ble_ias.html).
- **"Left the phone behind" alert and hot/cold finder** (own idea, no source needed): the Cardputer already holds the link, so it knows when the iPhone disconnects and can read the link RSSI. (a) Beep and show "iPhone out of range" when the link drops unexpectedly (not on a planned reset) — useful leaving a bar or the office. (b) A finder screen showing RSSI as a bar that grows as you approach the phone. **Feasibility** high (NimBLE exposes RSSI of a connection). **Effort** S. Fit: strong for "phone in pocket" — you notice when it is no longer in the pocket.
- **Camera shutter**: Volume Up (consumer usage 0xE9), press then release, takes a photo in the Camera app; the iPhone 16 Camera Control button cannot be triggered by HID (Apple DTS). Tasca's consumer report already carries any usage. Use: group photos with the phone on a stand, Cardputer in hand. **Feasibility** high. **Effort** S (a key, plus the volume keys from round 1). Sources: [Nordic: iOS shutter via BLE](https://devzone.nordicsemi.com/f/nordic-q-a/92798/trigger-ios-shutter-via-ble-on-ios-16), [Apple forum: Camera Control via HID](https://developer.apple.com/forums/thread/764062), [AB Shutter 3 key codes](https://dev.to/wincentbalin/key-codes-on-ab-shutter-3-2n0h).

### Using the Cardputer's own hardware (round 7)

Cardputer v1.1: ESP32-S3FN8 (8 MB flash, **no PSRAM**), SPM1423 MEMS microphone, IR emitter (≈4 m ahead), microSD, speaker 1 W, one Grove port. The newer Cardputer-Adv adds an ES8311 codec and a BMI270 IMU; the v1.1 is marked end-of-life by one listing. Sources: [M5Stack Cardputer v1.1 docs](https://docs.m5stack.com/en/core/Cardputer_v1.1), [Cardputer-Adv docs](https://docs.m5stack.com/en/core/Cardputer-Adv).

- **Voice on the Cardputer itself**: Espressif ESP-SR offers a wake word (WakeNet) and up to 300 fixed English commands (MultiNet), but recommends PSRAM, which the v1.1 lacks; no free dictation. The mic cannot reach the iPhone as audio (no Bluetooth Classic). Verdict: low; Siri through the iPhone's mic or earphones stays the voice path. Sources: [ESP-SR command words](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/speech_command_recognition/README.html), [CNX: ESP-SR](https://cnx-software.com/?p=116545).
- **IR remote**: the IR emitter can drive TVs, projectors and air conditioners (NEC/Sony/RC5 codes, e.g. IRremoteESP8266). Not iPhone-related, but it replaces "TV remote" apps on the phone. **Feasibility** high, **Effort** S–M, **Fit** medium (off-topic for a notifications device; a hidden Fn screen at most).
- **microSD**: (a) keep Messages across restarts — conflicts with the privacy decision "RAM only", so only as an opt-in; (b) offline notes typed on the Cardputer and later typed into the iPhone in Keyboard mode ("paste" a note as keystrokes) — useful for drafting a long WhatsApp reply first and sending it in one go. **Feasibility** high, **Effort** S–M. **Fit** good for (b): write while the phone stays in the pocket, send when ready.
- **Draft-then-send without SD** (variant of (b)): a draft buffer in RAM, edited on the Cardputer screen with full cursor editing, then sent to the iPhone as keystrokes with Enter. Avoids typing blind into the iPhone (today the echo line is the only feedback). **Effort** S–M. Strong fit.

### EU: iOS 26.5 notification forwarding and Live Activities for third-party wearables; Focus (round 8)

- **What changed (EU only)**: under the DMA, iOS 26.5 adds for third-party wearables (a) forwarding of "real" iPhone notifications, with responses on the device (heise), (b) Live Activities on the wearable (timers, rides, deliveries, sports scores), (c) AirPods-like proximity pairing. Notifications go to one wearable at a time (an Apple Watch stops mirroring). New frameworks: Accessory Notifications and Accessory Live Activities, governed by license section 3.3.3(J): no ads/profiling/AI training/location tracking, data decrypted only on the accessory, no cloud storage. Developers must declare use and receive an **entitlement**; reports differ on actions (one says no reply/dismiss/mute, heise says replies possible). Frameworks were undocumented at the time.
- **What it means for Tasca**: the user is in Italy, so this applies. But the frameworks are iOS-app APIs: they need an iPhone companion app with an Apple-granted entitlement (paid developer account), contrary to Tasca's "no app on the iPhone" principle. Gain over ANCS: Live Activities (delivery ETA, timers, next turn in Maps?) and possibly replies. **Feasibility** low today (entitlement, app, undocumented); **watch item**: re-check when Apple documents the frameworks and whether a non-app (BLE-profile) route appears. Sources: [MacRumors: privacy rules](https://www.macrumors.com/2026/03/31/apple-sets-privacy-rules-live-activities-alerts/), [heise: third-party wearables in the EU](https://heise.de/-11243346), [Beebom: iOS 26.5 forwarding](https://gadgets.beebom.com/news/ios-26-5-airpods-like-pairing-notification-forwarding-third-party-wearables-eu), [Gadget Hacks: limits](https://apple.gadgethacks.com/news/how-apple-privacy-rules-for-third-party-notifications-and-live-activities-limit-wearables/).
- **Focus**: iOS filters by Focus before ANCS, so a silenced app never reaches the Cardputer (already in the README). Community reports say third-party wearables sometimes get nothing under a non-DND Focus, even allowed apps: worth a test on the user's iPhone. Idea: a Focus toggle key via a Shortcut (round 2): "Work Focus on" from the Cardputer. Whether ANCS marks time-sensitive notifications as Important is undocumented; Tasca could log the Important flag to find out. Sources: [Apple Community: Focus and third-party wearables](https://discussions.apple.com/thread/253357788), [Apple: notifications on iPhone and Watch](https://support.apple.com/108274).

### System navigation from the keyboard; "open this chat" macro (round 9)

- **Built-in shortcuts** (iOS 26, Apple guide + AbilityNet): Fn/Globe+H Home Screen, Fn/Globe+Up App Switcher, Fn/Globe+C Control Center, Fn/Globe+N Notification Center (these under Full Keyboard Access), Cmd+Space Spotlight search; Cmd+Tab reported working on iPhone by a user, not documented. Sources: [Apple: control iPhone with an external keyboard](https://support.apple.com/en-bn/guide/iphone/ipha4375873f/ios), [AbilityNet iOS 26](https://mcmw.abilitynet.org.uk/how-to-control-your-device-using-an-external-keyboard-in-ios-26-on-your-iphone-or-ipad), [AppleVis: using my iPhone like a Mac](https://applevis.com/comment/209967).
- **Globe key is gated**: Apple's Globe/Fn is a vendor usage (page 0xFF, usage 0x03, AppleVendorTopCase KeyboardFn) that iOS honours only on keyboards with Apple vendor/product IDs; custom firmwares report it partly ignored. Workaround: iPhone Settings > General > Keyboard > Hardware Keyboard > Modifier Keys can remap Caps Lock (or Ctrl/Option) to Globe — Tasca sends Caps Lock, the iPhone treats it as Globe. To test. Sources: [Apple forum: AppleVendorTopCase KeyboardFn](https://origin-devforums.apple.com/forums/profile/rakic/comments), [ZMK issue 947: Globe key](https://github.com/zmkfirmware/zmk/issues/947), [mybyways: enable Globe on external keyboards](https://mybyways.com/blog/enable-the-globe-key-on-external-keyboards-for-ipad).
- **"Open this chat on the iPhone" macro** (own idea, to test): from a Chat screen, one key makes Tasca switch to Keyboard mode and send Cmd+Space, type the Chat name, wait, Enter. Spotlight lists WhatsApp conversations as suggestions (Siri suggestions learn frequent chats), so Enter may open the chat directly, ready for typing. Removes the main "take the phone out" step of replying. Needs the iPhone unlocked; risk: Spotlight picks a contact card instead of the WhatsApp chat. Alternative: a Shortcut "Open WhatsApp chat" via the `whatsapp://send?phone=` URL — needs the number, which ANCS does not give. **Feasibility** medium (test). **Effort** S. **Fit**: excellent if it works.
- **Notification Center from the Cardputer**: Globe+N opens it on the iPhone screen — not useful in a pocket; the Cardputer Inbox already covers it. Low.

### Hearing messages in the earphones (round 10)

- **Announce Notifications (Siri)**: iOS reads new notifications in the earphones while the iPhone is locked and listens for a spoken reply ("Reply…"); WhatsApp and Telegram support it. Officially AirPods and Beats only; a user reports Sony WH-1000XM5 doing it on iOS 26. One report: WhatsApp announced only as "<name> sent a WhatsApp message", not the text. Not something Tasca implements — a **README tip** (iPhone setup: Settings > Notifications > Announce Notifications) that pairs with the Cardputer: read on screen when you can look, hear it when you cannot, reply by voice or on the keyboard. Possible Tasca hook: a key that sends the Voice Command usage (Fn+Enter) right after an announced message to answer. **Feasibility** high (iPhone feature), **Effort** S (docs). Sources: [Apple: Announce Notifications](https://support.apple.com/en-ca/102536), [MacRumors: Announce Messages](https://www.macrumors.com/how-to/use-announce-messages-with-siri-on-iphone/), [Telegram first third-party app](https://www.macrumors.com/2020/12/02/telegram-first-to-use-announce-messages-with-siri/), [TidBITS: non-Apple headphones on iOS 26](https://talk.tidbits.com/t/audio-for-text-messages/32735), [Apple: respond with AirPods](https://support.apple.com/en-ke/guide/airpods/dev8c670727e/26/web/26).
- **Read a Message aloud from the Cardputer**: iOS has no route to speak arbitrary Cardputer text through the iPhone. VoiceOver keyboard commands (VO-A read all, VO-M status bar to Notification Center) work from an external keyboard but need VoiceOver on, which changes how the whole iPhone is used: not suitable. The Cardputer speaker could do on-device TTS (e.g. ESP8266SAM-style formant synthesis) — robotic and English-only, not through the earphones. **Feasibility** low. ### AMS protocol details for a future spec (round 11)

From Google Bumble's AMS client (open-source, matches Apple's appendix):

- **Remote commands** (one byte written to Remote Command): Play 0, Pause 1, TogglePlayPause 2, NextTrack 3, PreviousTrack 4, VolumeUp 5, VolumeDown 6, AdvanceRepeatMode 7, AdvanceShuffleMode 8, SkipForward 9, SkipBackward 10, LikeTrack 11, DislikeTrack 12, BookmarkTrack 13. Remote Command notifies the list of commands currently available (e.g. a podcast offers Skip ±, Spotify offers Like) — the Cardputer can show only the keys that work.
- **Entities / attributes**: Player 0 (Name 0, PlaybackInfo 1, Volume 2), Queue 1 (Index 0, Count 1, ShuffleMode 2, RepeatMode 3), Track 2 (Artist 0, Album 1, Title 2, Duration 3). EntityUpdateFlags bit 0 = truncated → read the rest through Entity Attribute, one at a time.
- **PlaybackInfo** = "state,rate,elapsed" as text, e.g. `1,1.0,42.5` (state 0 paused, 1 playing, 2 rewinding, 3 fast-forwarding). The elapsed time is a snapshot: the progress bar is extrapolated locally with rate × time since the update — no polling, so cheap on battery.
- **Cost on Tasca**: one more GATT client on the existing encrypted link, discovered like ANCS; notifications only on change (track, play state, volume). Memory: a few hundred bytes of strings. The "Like" command (11) maps to Spotify's like on some versions — to test.
- **Suggested shape** (for `/sdd:po`): a "Now playing" screen (Opt+m?) with title/artist/app, progress bar, volume; keys `,`/`/` previous/next, Space play/pause, `;`/`.` volume, `l` like; a one-line now-playing in the status bar or Keyboard mode context while music plays. With Spotify, expect artist mixed into the title on some devices (Adafruit note).
- Sources: [Bumble ams.py](https://github.com/google/bumble/blob/main/bumble/profiles/ams.py), [Apple AMS spec](https://developer.apple.com/library/ios/documentation/CoreBluetooth/Reference/AppleMediaService_Reference/Specification/Specification.html).

### Telling apps apart: more chat apps in the Inbox (round 12)

- **How Tasca would recognise apps**: the ANCS AppIdentifier attribute is the iOS bundle ID; the app's display name comes from the ANCS "Get App Attributes" command (DisplayName), so no hard-coded names are needed beyond a whitelist. Bundle IDs (case-sensitive): WhatsApp `net.whatsapp.WhatsApp`, Instagram `com.burbn.instagram`, Signal `org.whispersystems.signal`, Telegram `ph.telegra.Telegraph` (seen as a watch-extension prefix; to confirm from a capture), Messages `com.apple.MobileSMS`, Mail `com.apple.mobilemail`, Calendar `com.apple.mobilecal`, Shortcuts `com.apple.shortcuts` (Apple's to confirm from a capture). Best check: log the identifier of each Social notification once on the user's iPhone (identifier only, no text — privacy).
- **Suggested shape** (for `/sdd:po`): a whitelist of apps in Settings (WhatsApp, Messages, Telegram, Signal, Instagram, Mail, Calendar, Shortcuts results), each on/off; a one-letter app badge on each Inbox row (W, M, T, S, I…); Chats keyed by app + chat name so "Mario" on WhatsApp and on Telegram stay apart. Memory budget unchanged (56 KB shared). Category filter: Social plus Email/Schedule only when those apps are on, to keep the reconnection import short (the decision that halved it to 5.6 s).
- **Feasibility** high. **Effort** M. **Fit**: very good — one screen for every conversation.

### Minimal-phone ideas applied to Tasca: priority and quiet (round 13)

Context: "companion" minimal devices (Meadow, Mudita Kompakt, Light Phone, Punkt) keep the smartphone but move daily use to a calmer device with deliberate friction and fewer, more important interruptions. Tasca already fits this niche: a keyboard-first companion with no feeds. Ideas borrowed, all on-device (no iPhone change):

- **Favourite Chats**: mark a Chat as favourite (key on the Chat screen, kept in NVS by name). Favourites beep and wake the screen; others arrive silently and only bump the unread count. Mirrors "you hear only from who genuinely wants to reach you". **Effort** S–M. **Fit** strong.
- **Quiet hours / batch delivery**: a Settings row "Quiet" (Off / until next hour / schedule). While quiet, no beep and no wake; a summary on wake ("12 new in 4 chats"). Needs the clock (CTS, round 4). **Effort** S once time is known.
- **Digest instead of live**: optional "deliver every 30 min" — Messages are stored live but the unread count and beep come at fixed times, so the user checks the Cardputer rarely. **Effort** S. **Fit** good for focus, to discuss with the user.
- **Keep it friction-free for replies only**: the other side of the minimal-phone design — replying from the Cardputer should be the easy path (draft-then-send, "open this chat" macro), reading feeds should not exist. Confirms leaving Instagram feed-like notifications (likes, follows) out, keeping only DMs (filter by notification text pattern or by subtitle).

### Faster and richer typing into the iPhone (round 14)

- **Emoji and canned replies via iOS Text Replacement**: Settings > General > Keyboard > Text Replacement maps a shortcut to any text or emoji sequence; it expands after a space or punctuation, also when typed on a hardware keyboard (to confirm on the user's iPhone). So Tasca can send emoji without Unicode tricks: the user defines `:ok` → 👍, `omw` → "Arrivo tra 10 minuti". Tasca side: optional key macros that type those shortcuts, e.g. Fn+1..9 = a quick-reply list shown on screen. Control-Space switches input language on iPhone (emoji picker on Mac is Ctrl+Cmd+Space; not confirmed on iPhone). **Feasibility** high. **Effort** S (README tip) to S–M (quick-reply list). **Fit** strong: one key for the common answers. Sources: [MacRumors: text shortcuts](https://www.macrumors.com/how-to/use-text-shortcuts-on-apple-devices/), [iPhone Life: emoji shortcuts](https://iphonelife.com/content/tip-day-use-emoji-shortcuts-instead-switching-keyboards), [Daring Fireball: Control-Space](https://daringfireball.net/linked/2020/03/30/moren-emoji-keyboard), [Gadget Hacks: text replacements](https://apple.gadgethacks.com/how-to/text-replacements-secret-weapon-typing-more-with-less-your-iphone-ipad-mac-0385508).
- **Sending whole strings (draft-then-send, macros)**: bursts of HID reports can drop or stall characters on iOS; Nordic users report the first characters lost and long pauses. Recommended pacing: 10–25 ms between press and release reports and a 15 ms connection interval (iOS accepts 11.25 ms for HID only sometimes, per Apple QA1931). Tasca already uses 15–30 ms (usual timings); the slow timings (120–150 ms) must be switched back before a macro. **iOS 26 note**: a Nordic thread reports iOS 26 sending connection-parameter updates to HID devices about every 120 ms and disconnect issues — worth watching in Tasca's `TimingsUpdate` logs. Sources: [Nordic: delay between characters](https://devzone.nordicsemi.com/f/nordic-q-a/988/nrf51822-hid-example---delay-between-characters), [Apple forum: HID interval 11.25 ms](https://developer.apple.com/forums/thread/796428), [Nordic: iOS 26 disconnect issues](https://devzone.nordicsemi.com/f/nordic-q-a/124994/ios-26-bluetooth-disconnect-issues/552466), [Punch Through: connection interval](https://punchthrough.com/ble-connection-interval-throughput/).
